# Разработка Vault Dock

ТЗ и результаты прототипа хранятся в проекте `Obsidian Vault Bar` в Obsidian
vault `life-balance`. Прототип внутри Yandex Disk Sync был временным.
Данный репозиторий собирает отдельный плагин с ID `vault-dock`.

## Сборка и установка в тестовые хранилища

Нужны Node.js 22 и npm. Установите зависимости командой `npm ci`.

- `npm run build` проверяет TypeScript и собирает `main.js`, `manifest.json` и
  `styles.css` в `build/`.
- `npm run dev` пересобирает эти файлы при изменениях.
- `npm run check` запускает линтер, проверку форматирования, сборку и тесты.
  Та же команда используется в GitHub Actions.

Чтобы автоматически копировать сборку в тестовые хранилища, скопируйте
`.env.example` в `.env` и укажите абсолютные пути к папкам плагина. Запишите
каждый путь с новой строки внутри одной пары кавычек.

```dotenv
VAULT_SWITCHER_PLUGIN_PATHS="
/path/to/test vault/.obsidian/plugins/vault-dock
/path/to/second vault/.obsidian/plugins/vault-dock
"
```

`npm run build` и `npm run dev` копируют три файла в каждую указанную папку.
Если список пуст, сборка использует прежний `VAULT_SWITCHER_PLUGIN_PATH`,
если он задан. Без путей файлы остаются в `build/`. Git игнорирует `.env`.
Проверки и CI пропускают установку из `.env`.

После смены ID обновите пути к папкам плагина в локальной конфигурации
на `.obsidian/plugins/vault-dock` для каждого тестового хранилища.

Для разовой установки откройте тестовое хранилище в Obsidian и передайте путь
к нему.

```sh
npm run install:dev -- --vault "/path/to/test vault"
```

`--vault` имеет приоритет над `.env` и работает также с `npm run build` и
`npm run dev`. После копирования включите или перезагрузите плагин в настройках
Obsidian.

## Проверенные ориентиры для реализации

- В установленном Obsidian 1.15.0 встроенный переключатель использует
  внутренние IPC-вызовы `vault`, `vault-list` и
  `vault-open(path, false)`. Первый даёт ID текущего vault, второй — реестр
  с ID и путями, третий открывает целевой vault или фокусирует его окно.
  Эти вызовы зависят от версии Obsidian.
- Для верхнего бара в прототипе использовался контейнер
  `.workspace-split.mod-left-split > .workspace-tabs > .workspace-tab-header-container`.
  Вставка идёт после заголовка, над содержимым левой панели. Перед использованием
  селектора в отдельном плагине проверь его в целевой версии Obsidian.
- В прототипе геометрия снималась через `window.electronWindow.getBounds()`.
  Целевое окно вызывало `setBounds()` и подтверждало запрос по ID операции.
  Источник закрывался после подтверждения. Факт успешного вызова
  `vault-open` подтверждает приём запроса, готовность окна проверяется
  отдельно.
- Временный прототип использовал общий `localStorage` для картинок и передачи
  запроса. Общность данных между окнами, готовность целевого окна и отсутствие
  визуального скачка требуют проверки в запущенном Obsidian. Один общий ключ
  запроса допускает перезапись при переходах из двух источников.

## Первый показ окна в Obsidian 1.15.0

На macOS диагностический плагин в двух временных vault’ах считывал `isVisible()` и
`getBounds()` в начале `onload()`, применял геометрию исходного окна и считывал её
повторно. В 20 холодных переходах (по 10 в каждую сторону) цель к этому моменту
уже была видима с сохранённой геометрией. После `setBounds()` геометрия совпадала
с исходным окном во всех 20 случаях. Например, при первом переходе B уже было
видимо в `(290, 175)` с размером `650 × 430`, а в `onload()` переместилось в
`(50, 65)` и приняло размер `520 × 380`. Замер фиксирует состояние Electron.
Запись экрана не проводилась.

В установленном клиенте `vault-open` принимает путь и флаг создания папки.
Клиент задаёт начальную геометрию из сохранённого состояния и вызывает `show()`
по `ready-to-show` или завершению `loadURL()`, в зависимости от того, что наступит
раньше. `@electron/remote` доставляет callback слушателя в renderer через IPC
асинхронно. Он не даёт синхронного перехвата создания окна. Для MWP нужен способ
передать геометрию при создании окна или гарантированно применить её до `show()`.
Текущая реализация применяет геометрию закрытого vault в начале `onload()`.
Для уже открытого vault геометрия применяется перед запросом фокуса. В обоих
случаях исходное окно закрывается после подтверждения от готового целевого.

Для уже открытого vault проба подтвердила применение геометрии перед запросом
фокуса и получение фокуса целевым окном. В том же профиле второе окно получило
событие `BroadcastChannel` и прочитало тестовый `Blob`, записанный первым окном
в IndexedDB. После пробы тестовые регистрации и данные диагностики удалены.

## Ручная проверка бара

1. Установить одну и ту же сборку в два тестовых vault’а. Проверить, что
   зарегистрированный из папки vault появился автоматически, а штатные нижние
   кнопки работают как прежде.
2. По правому клику на плитку загрузить, сменить и удалить картинку. Проверить,
   что меню открывается и на активной плитке, удаление недоступно без картинки,
   а отмена выбора и неподдерживаемый файл сохраняют прежнюю картинку.
   Проверить второе окно и перезапустить Obsidian. Для двух одноимённых vault’ов
   убедиться, что плитки открывают нужные папки по левому клику.
3. Проверить переход в закрытый и уже открытый vault. Изменить размер и
   позицию источника и повторить переход в обе стороны. Проверить состояние
   редактора и фокус после перехода.
4. Проверить ошибку открытия, таймаут готовности, быстрые клики и запоздалое
   подтверждение. Исходное окно остаётся доступным при сбое.
5. Отдельно проверить узкую боковую панель, максимизацию, полноэкранный режим
   и несколько мониторов.
6. В режиме **Hide current window** вернуться в скрытый vault и проверить, что
   вкладки и позиция курсора сохранились. Закрыть активное окно красной кнопкой
   macOS и проверить, что скрытые при переключении окна тоже закрылись, а
   нажатие иконки Obsidian в Dock снова открывает окно. Отдельно сменить режим
   в настройках и убедиться, что скрытые плагином окна снова доступны.
7. В режиме **Keep both windows open** проверить переход без переноса координат и
   открытие цели с выключенным плагином. Убедиться, что плитки источника
   доступны во время открытия. В обоих режимах с переносом геометрии проверить
   цель без плагина, сначала закрытую, затем уже открытую. Цель должна принять
   позицию и размер источника, получить фокус, а источник — закрыться.
   Повторить с включённым **Restricted Mode** в цели, в которой плагин до
   этого был включён. Для проверки каскада открыть A, B и C, оставив
   плагин выключенным только в C. В режиме **Hide current window**
   переключиться из A в B, затем из B в C. Когда C получит фокус,
   B закроется, а вслед за ним закроется скрытое A.
   Отключить общие настройки, выбрать разные режимы и картинки в двух
   vault’ах, затем включить общие из одного vault’а и проверить, что второй
   получил весь его набор.
8. Прокрутить ряд плиток в узкой панели, перевести клавиатурный фокус на плитку
   и переключиться на другое приложение. Вернуться в Obsidian и проверить
   позицию прокрутки и фокус плитки. Изменить картинку во втором окне и
   убедиться, что первое окно показывает её после обновления.
9. Открыть цель в максимизированном окне и закрыть её. Из обычного окна
   переключиться в неё в режиме **Keep windows open**. Повторить с уже открытой
   целью в полноэкранном режиме macOS. В обоих случаях цель должна принять
   размер и позицию источника и получить фокус. Источник скрывается, а при
   возврате сохраняет вкладки. Повторить перенос в режиме **Replace window**
   и с выключенным плагином в цели. Исходное окно в этих случаях закрывается.
10. Свернуть целевое окно в Dock и переключиться в него из обычного окна.
    Повторить с включённым и выключенным плагином в цели. Цель должна
    восстановиться, принять геометрию источника и получить фокус.
11. Открыть штатное меню внизу боковой панели и сверить отмеченный режим с
    настройками Vault Dock. Выбрать другой режим в меню, проверить его в
    настройках и во втором хранилище при общей области. Повторить при раздельных
    настройках. В каждом режиме выбрать хранилище через штатное меню и через
    плитку. Оба перехода должны одинаково обрабатывать видимые, скрытые и
    закрытые целевые окна. При отмене выбора или ошибке открытия исходное
    окно остаётся доступным.

В изолированном профиле Obsidian 1.15.0 на macOS прежняя сборка воспроизвела
ошибку холодного перехода в максимизированную цель. С новой сборкой прошли
холодный переход и переход в уже открытое полноэкранное окно с сохранением
вкладки при возврате. Для полноэкранной цели с выключенным плагином проверены
перенос геометрии, получение фокуса и закрытие исходного окна.

## Совместимость картинок и смена области настроек

Проверять в Obsidian 1.15.0 на двух тестовых vault’ах с включённым плагином.

1. До обновления сборки включить общие настройки и назначить разные тестовые
   картинки двум плиткам. После обновления убедиться, что обе картинки
   сохранились и отображаются в обоих окнах.
2. В первом окне открыть выбор новой картинки и оставить файловый диалог
   открытым. Во втором окне отключить **Share settings across vaults**.
   Завершить выбор в первом окне. Должно появиться сообщение об ошибке
   сохранения, а картинка плитки должна остаться прежней.
3. Выбрать разные режимы и картинки в обоих vault’ах. Включить общие настройки
   из второго окна. Проверить, что в первом окне сразу появился весь набор
   второго окна, включая режим и картинки.
4. Перезапустить Obsidian и сверить режим, область и картинки в обоих окнах.

Тест сборки проверяет загрузку CommonJS-модуля со сторонним API Obsidian и
состав файлов установки. Она не проверяет внешний вид и Electron IPC.

## Положение панели

В Obsidian 1.15.0 встроенная нижняя панель `.workspace-sidedock-vault-profile`
имеет `order: 1`. В нижнем положении бар плагина стоит перед ней и использует
тот же порядок, чтобы обе панели располагались после вкладок. Для бара плагина
нужно явно задать высоту по содержимому и отключить растягивание, поскольку
Obsidian растягивает прямых потомков вертикальной боковой панели.

1. Открыть два тестовых vault’а с включённым плагином. При первой установке
   панель в обоих окнах находится под вкладками. Перебрать четыре значения
   **Положения панели** и проверить, что второе окно обновляется сразу.
2. Отключить **Общие настройки для всех хранилищ** и снова сменить положение.
   Панель должна переместиться в обоих окнах. Перезапустить Obsidian и
   убедиться, что выбранное положение сохранилось. После обновления со старой
   версии с включённым **Показывать панель внизу** должно быть выбрано **Снизу**.
3. В обоих вертикальных положениях свернуть и раскрыть боковые панели.
   Скрыть ленту иконок и проверить перенос левой полосы к краю рабочей области.
   Убедиться, что плитки доступны, а строка состояния, меню штатного
   переключателя и кнопки внизу боковой панели работают.
4. В коротком окне с несколькими плитками прокрутить вертикальную полосу до
   конца и проверить, что последняя плитка доступна. Сменить картинку из
   второго окна и проверить сохранение прокрутки и клавиатурного фокуса.
   Открыть контекстное меню и переключиться в другое хранилище через плитку.
